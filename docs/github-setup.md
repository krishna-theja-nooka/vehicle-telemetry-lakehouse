## Workflows, release and package

1. Commit both `.github/workflows/ci.yml` and `.github/workflows/release.yml` on `main`.
2. Open **Actions → CI**. Wait for a successful run. If it fails, inspect the failed step before publishing.
3. Open **Actions → Release and publish package → Run workflow**, select `main`, and run it once.
4. This workflow reruns checks, builds the Python wheel and source ZIP, builds and health-checks the container, pushes the versioned GHCR image, then creates the release and tag from the tested commit. The initial version is `v0.1.0`.
5. Do not manually create the same release first: the workflow refuses an existing release. Later releases require updating `pyproject.toml` and `RELEASE_NOTES.md`.
6. Open the package after publication and review its visibility. For anonymous public downloads, set the package visibility to **Public** if it is private. The workflow associates the image with this repository through the source label and token.

The workflow uses GitHub's automatic `GITHUB_TOKEN`; no Docker Hub account or personal token is needed. Organization policies can restrict package publication. If the image push succeeds but release creation fails, inspect the log and rerun; the versioned container can be pushed again. A workflow file alone does not create a release or package until it runs successfully.
